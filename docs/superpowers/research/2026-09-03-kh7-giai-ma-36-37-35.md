## 3. Ba gói — bảng byte đầy đủ

### 3.1 `-36` túi (client `Controller.cs:2202-2263`, Java `:561-602`)

```
[cAction: byte = 0]
[soO: unsigned byte]            <- Controller.cs:2208 readUnsignedByte
( MỘT MÓN hoặc [short -1] ) × soO
```

- `cAction` đọc bằng `readByte()` (có dấu, `:2204`); chỉ `0` là "nạp cả túi",
  `2` là "đổi số lượng một ô" (`:2248-2262`, thân `[byte oSo][int soLuongMoi]`).
  Giá trị khác: client **không làm gì** và không lỗi.
- `soO` đọc **không dấu** (≤255) nhưng Java ghi `writeByte` **có dấu** (≤127).
  Bản Go kẹp **127** — xem §5.

### 3.2 `-37` đồ đang mặc (client `Controller.cs:2005-2054`, Java `:604-646`)

```
[cAction: byte = 0]             <- khác 0 thì client BREAK ngay (:2007)
[head: short]                   <- :2011, đầu nhân vật
[soO: unsigned byte]            <- :2013
( MỘT MÓN hoặc [short -1] ) × soO
```

- Sau mỗi món client đọc `template.type` để gán `body`/`leg` (`:2043-2051`) —
  **không đọc thêm byte nào**, chỉ tra bảng mẫu đã nạp bằng `-28/8`.
- Vị trí ô cố định (Java `Player.java:878-882`): 0 áo · 1 quần · 2 găng · 3 giày · 4 nhẫn.

### 3.3 `-35` rương (client `Controller.cs:2265-2322`, Java `:648-697`)

```
[cAction: byte = 0]
[soO: unsigned byte]            <- :2271
( MỘT MÓN hoặc [short -1] ) × soO
```

Giống hệt `-36` về thân. Lệnh con `1` = "mở giao diện rương": client cố đọc thêm
**một byte `isBoxClan`** trong `try/catch` rỗng (`:2303-2318`) trong khi Java gửi
gói rỗng (`:691-693`) — đó là lệch **L7** của đặc tả. Bản Go **ghi đủ byte đó**.

## 4. Bẫy L1 — xác nhận bằng mắt trên cả hai file

- Java `-36` (`InventoryService.java:567-572`): ghi `soMon = itemsBag.size()` rồi
  `if (!item.isNotNullItem()) continue;` — **không ghi `-1`**.
- Java `-37` (`:612-613`) và `-35` (`:655`): ô rỗng **có** ghi `writeShort(-1)`.
- Client `-36` (`:2212-2218`) luôn lặp đủ `soO` lần và chỉ bỏ qua khi đọc được `-1`.

→ Túi có ô trống ở giữa ⇒ gói thiếu byte ⇒ client đọc lấn sang phần khác ⇒
`IndexOutOfRangeException` (`myReader.cs` đọc `buffer[posRead++]` không kiểm biên)
⇒ bị `catch (Exception) { }` rỗng (`Controller.cs:118-122` … `:4600-4602`) nuốt sạch.
**Không lỗi, không log, hành trang hiện dở dang.**

**Bản Go: cả ba gói đều ghi `short -1` cho ô rỗng.** Không dựa vào việc dồn ô trống
về cuối.

## 5. Trần số ô — con số có căn cứ

| Trường | Client đọc | Java ghi | Bản Go chọn |
|---|---|---|---|
| `soO` của `-36` / `-35` | `readUnsignedByte()` ≤ 255 | `writeByte` có dấu ≤ 127 | **127** |
| `soO` của `-37` | `readUnsignedByte()` ≤ 255 | `writeByte` có dấu ≤ 127 | **127** (bản 1 dùng 5) |

Vì sao 127 chứ không 255: đặc tả §8 điểm 3 + §4.2. Trần thật của giao thức là 255,
nhưng ME_INFO (`thegioi.go`, spec vào thế giới §11.2) ghi `itemsBag.size` /
`itemsBox.size` bằng **byte CÓ DẤU** — quá 127 là số âm ở đó. Hai chỗ phải cùng một
con số, nên trần chung là **127**. Đây là lựa chọn *an toàn*, không phải giới hạn
tuyệt đối; nới lên phải sửa cả ME_INFO trước.
